# 传统检测器 v2

当前阶段优先提高 CPU/OpenCV 单帧检测效果，并固定后续 YOLO、追踪器和位姿解算需要的观测契约。未接入预测器，未以小陀螺的瞄准、命中或整车状态估计作为本阶段验收指标。

## 改动与依据

旧版要求灰度大于 170 且红蓝通道差大于 70。旋转视频第 235 帧一侧红灯区域最高灰度仅约 146，另一侧只剩零散高亮像素；提高配对容差无法恢复已被分割丢掉的灯条。v2 改为红灯使用 R 通道亮度、蓝灯使用 B 通道亮度，同时保留通道差分抑制白色数字。

运动拖影还会把细长灯条变成宽亮斑。v2 选择矩形中更接近竖直的边计算长宽比，避免长边因横向拖影翻转 90°。达到可靠长宽比的灯条保留拟合端点；其余亮斑沿配对中心连线的法向投影，输出近似端点，并保留较低的角点质量。两侧至少一侧方向不可靠时，要求有板内图案支持。

配对保留长度比、中心连线倾角、归一化间距等限制；仅对可靠方向使用严格平行/垂直关系。灯条之间的板面区域被缩放到小图，统计具有竖向跨度的中性亮笔画，辅助区分数字板和相邻板间的横向反光。这不是数字分类器，`target_id` 仍为 0。

跨过内部灯条的配对被拒绝。为避免只检测红色时跨过蓝色装甲板，提取阶段始终保留两色灯条作为阻挡信息，颜色配置只限制配对输出。按启发式分数选择配对后，排除共用灯条和同色重叠多边形。

## 参数与诊断

`config/traditional.yaml` 与 `TraditionalDetectorParams` 默认值一致。运行层使用 OpenCV FileStorage 读写 YAML，无额外依赖；`config_version: 2` 固定了通道亮度的语义。文件可仅覆盖部分参数，省略项使用默认值。未知或重复键、错误类型、非法取值会被拒绝。

推荐先查看 `diagnostics.csv` 定位损失阶段，再调参数：

| 诊断项 | 含义 |
|---|---|
| `contours`、`rejected_area` | 原始轮廓数量及面积过滤损失 |
| `rejected_light_geometry` | 长度、长宽比或倾角不合格 |
| `lights`、`uncertain_lights` | 保留灯条及其中方向不可靠的数量 |
| `pairs`、`rejected_pair_geometry` | 所选颜色的同色配对数量及几何过滤损失 |
| `rejected_intermediate` | 内部灯条阻挡造成的拒绝 |
| `rejected_corners` | 四点越界、非凸或退化 |
| `rejected_score` | 几何/图案综合分数或模糊候选图案支持不足 |
| `candidates`、`suppressed` | 评分后候选及去重数量 |

每帧统计独立清零。满足 `contours = rejected_area + rejected_light_geometry + lights`；`pairs` 等于各类配对拒绝数量加 `candidates`；最终输出数量为 `candidates - suppressed`。

图案阈值针对板内白色笔画，与灯条通道亮度阈值分开。只有清晰灯条时允许无图案观测；模糊且图案不可见时会更保守。若要评估无数字装甲板，可单独设置 `min_blob_pattern_score: 0`，同时观察反光和跨板误检，保留配置快照。不能直接以候选变多判断调参成功。

## 检测器、YOLO 与追踪器的边界

数据流保持 `ImageFrame -> Detector -> DetectionFrame -> Tracker`。当前仍为同步单帧接口，无模型后端依赖，也没有实现目标运动预测。

| 字段 | 约定 |
|---|---|
| `source_sequence`、`capture_time` | 保留输入帧序号和采集时刻；空观测也必须传递 |
| `bounding_box`、`corners` | 原图像素坐标，不暴露裁剪/网络缩放坐标 |
| `corners` 顺序 | 左上、右上、右下、左下灯条端点 |
| `source` | 当前为 `traditional`；网络适配器使用 `neural` |
| `score_kind` | 当前为 `heuristic`；模型分数使用 `model` |
| `confidence` | 后端自身的排序分数，不可跨后端直接共用阈值 |
| `geometry_score` | 本次传统几何检查的评分，不含板内图案得分 |
| `corner_quality` | [0,1] 的灯条方向可靠程度，取两侧较低者；不是像素误差或概率 |
| `corners_valid` | 仅表示四点有限、在图像内且构成非退化凸四边形 |
| `target_id` | 数字类别；0 表示未知，不是追踪身份 |
| `track_id` | 由未来追踪器分配；当前占位追踪器始终为 0 |

后续网络适配器需自行还原缩放和裁剪偏移、统一角点顺序，并按实际能力填写质量信息。网络若输出整板外角点，不能直接冒充当前契约中的灯条端点用于 PnP。未知角点质量保留默认 0。检测列表按横坐标排序不代表稳定身份；身份关联属于追踪器。

`TraditionalArmorDetector::refineCorners(frame, detection)` 提供可选修正：

1. 在原观测附近裁剪并运行同一传统检测链路；处理结果还原到原图坐标。
2. 只接受同色、两侧方向都可靠、四点逐一靠近原观测的候选。
3. 成功更新角点、包围框、几何分数和角点质量，保留原来的来源、评分种类、模型分数与数字类别。
4. 未找到可靠灯条时返回 `false`，不修改输入观测，调用方继续使用网络结果。

角点修正不能保证提高真实像素精度，它只在找到可靠且接近的灯条时尝试修正。当前通过合成清晰灯条验证坐标恢复与失败保持，仍需网络/相机数据验证收益。

`rmvision_tracker` 已纳入构建，当前 `SimpleTracker` 仍只取首个观测中心、空观测立即失效；它现在保留采集时间，尚不提供卡尔曼滤波、身份关联、短时丢失保持或预测。未来 YOLO 应作为独立可选构建目标，不使纯 OpenCV 构建依赖推理 SDK。

## 复现与结果

在项目根目录运行：

```bash
cmake --preset debug -DRMVISION_BUILD_TESTS=ON
cmake --build --preset debug
ctest --test-dir build/debug --output-on-failure
./build/debug/bin/rmvision_hello
./build/debug/bin/detector_video_test \
  'tests/media/旋转装甲板.mp4' build/video_test/traditional_v2 \
  --config=config/traditional.yaml --threads=1
```

本地原始媒体不提交到 Git。视频报告保存 `parameters.yml`、逐帧诊断、候选四点和质量，以及原帧率标注视频。重新执行会覆盖相同输出目录，比较实验时需换目录。

本次开发使用本地 1920×1080、59.94 FPS、647 帧的旋转视频：

| 指标 | 旧版 v1 | v2 默认配置 |
|---|---:|---:|
| 有输出的帧数 | 24 | 340 |
| 有输出帧占比 | 3.71% | 52.55% |
| 最长连续空检测 | 246 帧 / 4.104 秒 | 14 帧 / 0.234 秒 |
| 静态样图 | 2 红、1 蓝 | 2 红、1 蓝 |

视频用于调参与目视复核，没有独立人工真值，以上不是准确率或召回率。多数动态观测仍属于低质量角点；标注视频中的 `h` 表示启发式分数、`q` 表示角点质量。仍可能存在跨板误检、反光、严重模糊和侧视漏检。低质量观测可供未来追踪器谨慎使用，不能直接作为精确姿态或小陀螺预测已经成功的证据。

回归包括静态实图、鲜红/鲜蓝低灰度灯条、BGRA、运动模糊、宽亮斑、圆形与横向反光、图案配对优先级、角点修正的成功/失败、配置校验以及空观测的接口时间信息。虚拟机耗时仅作为开发诊断，部署帧率和 P95 需在目标实机测量。
